# Intelligent Process Observer

Intelligent Process Observer is the implementation workspace for a master-thesis MVP focused on intelligent multi-agent observation, anomaly analysis, and supervision of technological processes.

The repository is a monorepo. Architectural decisions are maintained separately from implementation specifications: the architecture package under `docs/architecture/` is the authoritative source for architecture and ADRs, while OpenSpec is used to define concrete behavioral changes before implementation.

## Development baseline

- Windows host with WSL2
- Ubuntu 22.04 LTS inside WSL2
- repository stored in the WSL Linux filesystem
- VS Code connected to WSL
- Docker Engine running directly in WSL2
- Python >= 3.13, managed with `uv`
- FastAPI, Pydantic, SQLAlchemy async, Alembic, PostgreSQL, Psycopg 3
- React, TypeScript, Vite, npm
- OpenSpec with the core workflow profile
- Codex as the primary coding agent, with OpenCode also supported

## Quick start

From the repository root:

```bash
make setup
make db-up
```

Start the backend in one terminal:

```bash
make backend
```

The shallow health endpoint is available at:

```text
http://localhost:8000/health
```

Start the frontend in another terminal:

```bash
make frontend
```

Run the complete local verification gate before a pull request:

```bash
make check
```

## OpenSpec bootstrap

OpenSpec-generated agent skills and commands are generated by the installed OpenSpec CLI rather than maintained by hand. During the initial workspace bootstrap, run from the repository root:

```bash
openspec init --tools codex,opencode --profile core
```

Review the generated files and commit them as part of the bootstrap pull request. After upgrading the OpenSpec CLI, refresh the generated integration files with:

```bash
openspec update
```

## Sources of truth

Use the following distinction consistently:

- `docs/architecture/` defines accepted architecture, architectural constraints, ADRs, and open/deferred decisions.
- `openspec/changes/` defines the behavioral change currently being planned or implemented.
- `openspec/specs/` accumulates accepted functional behavior from completed changes.
- source code implements those decisions and specifications.

Do not infer requirements from architecture items marked `Open` or `Deferred`.
